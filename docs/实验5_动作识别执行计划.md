## 4. 报告增量点（写给统稿人）

- **第七/九章加一节"视觉动作识别"**：18→13+背景归并表、7424 clip 构建口径（tube 逐帧框裁剪 + 检测器采背景）、双档训练结果表（acc/macro recall/参数量）、混淆矩阵图（`train_summary.json` 直接画）；

  双档实测（官方 val 视频集 2061 clip）：

  | | mc3_18（部署档） | r2plus1d_18（精度档） |
  |---|---|---|
  | 参数量 / ONNX 体积 | 11.6M / 45.98MB | 31.0M / 125.2MB |
  | test acc | 84.38% | 84.23% |
  | test macro recall | 64.14% | 64.66% |
  | dev acc / macro recall（best epoch） | 86.65% / 68.72%（18/20） | 86.49% / 69.23%（12/20） |
  | T4 稳态每 epoch / CPU FP32 每 clip | 139s / 326ms | 258s / 305ms |

  结论：**2.7× 参数量在 7424 clip 规模上零收益（瓶颈是数据不是容量）**；r2plus1d 因子分解卷积（3×3×3 → 空间+时间两步）CPU 推理反而略快。逐类互有胜负：mc3 赢 shot_3p（93% vs 80%）、pick_roll_def（72% vs 56%）；r2 赢 free_throw（81% vs 63%）、背景类（100% vs 97%）；block 两档皆 0（14 例）。
- **两个可讲的负结果**：① INT8 动态量化在 3D 卷积上慢 28×（340ms→9.5s/clip），与实验3 的 2D 检测器结论相反——量化收益依赖算子形态，部署选 FP32；② 长尾类（block 30 例/steal 75 例）召回必然偏低，归并策略是数据现实约束下的取舍；
- **闭环叙事升级**：检测（谁）+ 动作识别（干什么）+ LLM（怎么说）——正好对应 TEAM_PLAN.md 第 183 行的原始定位，且"解说禁令"从"不许提投篮"升级为"只许用识别出的动作"。
