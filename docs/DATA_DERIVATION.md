# 数据与系统推导 v4 —— 终态：AI 篮球赛事解说员（两类数据版）

> v4 定稿：砍掉 Kaggle 统计表主线，数据采集收敛为两条线。
> 终态不变：上传比赛视频 → AI 跟着画面逐事件生成解说（文字流，加分 TTS）。

## 1. 终态与倒推

好解说员 = 看得懂画面 + 嘴上有风格（两要素版）：

| 要素 | 能力 | 数据来源 |
|---|---|---|
| 看得懂画面（谁、在哪、做了什么动作） | 检测 + 跟踪 + 动作识别 | **采集线 ①：MultiSports 篮球子集** |
| 嘴上有风格（术语、节奏、解说语言） | LLM 微调 + RAG | **采集线 ②：文字直播解说语料** |


## 2. 两条采集线 → 三类数据形态

```
采集线① MultiSports 篮球子集（MCG-NJU，HuggingFace，✅ 2026-10-11 已抽样验证）
  ├─ 视频：mp4 文件（1280×720@25fps，每段约 31s，转播画面含比分栏）
  ├─ 截帧图像 + 逐帧球员框(tube) ──> YOLO 训练数据（实验2/3）
  └─ 动作实例标注 ──转事件表──> 结构化事件数据（时间/球员/动作/位置）
                                  = Agent 解说的事实依据
                    

采集线② 文字直播爬取（直播吧/新浪，改 crawl_basketball_news.py）
  └─ 解说语料（逐条带时间戳）──> RAG 语料库 + LoRA 微调指令数据（实验5）
```

### 采集线② 侦察结论（2026-10-11 实测）

| 候选源 | 实测结果 | 结论 |
|---|---|---|
| **直播吧主站** www.zhibo8.com | robots 404=允许；首页服务端内嵌完整赛程（`var schedule`，8 天 130 场篮球，含每场"文字"链接 `/zhibo/nba/2026/match{id}v.htm`）；但**文字直播由 JS 在比赛进行中轮询加载，赛后页面不保留**（实测 10/10 已结束的灰熊vs公牛页只剩"直播暂未开始"占位）；NBA 场次文字信号非场场有 | ✅ 可用，**须比赛时段实时抓** |
| 新浪 slamdunk NBA 数据库 | 页面 2017 年发布、`MatchConfig season:2021`，系统已停更 | ❌ 废弃 |
| NBA 官方 cdn.nba.com playbyplay JSON | 本网络超时（需代理）；英文事件文本 | ⏸ 非必需（事件结构已由 MultiSports 覆盖） |
| 虎扑 match.hupu.com | 反爬强，逆向成本高 | ⏸ 备选 |

**解说语料获取方案（两级）**：
1. **主案：直播吧缓存接口批量补爬 ✅ 采集完成并封账（2026-10-11 晚）**——逆向成功：文字直播数据在 `dingshi4pc.qiumibao.com/livetext/data/cache/livetext/{场次ID}/0/page_10/{序号}.htm`（JSON，每页 10 条，33 字段：解说文本/时间戳/解说员/当时比分等），**已结束场次完整保留**，无需守直播。爬虫 `crawl_zhibo8_livetext.py`（限速 0.5s/页、3 并发、直连绕系统代理、断点续爬、课程 UA）；ID 来源：首页 schedule+recordData（篮球频道）+ NBA 新闻频道战报链接 + 季前赛 more.htm 历史 ID。
2. **过渡案**：已爬 122 篇资讯继续作为背景知识 RAG 语料。

**语料采集最终结果（封账）**：41 场有解说的完整比赛、4.09 万条原始记录；清洗去空行/超短行/重复后 **40,376 条**，按场次 8:1:1 防泄漏划分：train 33 场 32,377 条 / val 4 场 4,889 条 / test 4 场 3,110 条（`data/processed/texts/livetext/`：commentary.jsonl + split_*.jsonl + clean_metrics.json）。规模已达"够 agent 学习"目标，不再扩采；每日增量爬取可选。

### 验证结论（2026-10-11，样本实测）

- **分发格式**：`data/trainval/basketball.tar`（15.55 GB）内为 **mp4 视频**（非帧序列），`basketball/v_xxx.mp4`，cv2 可正常读取抽帧；
- **篮球子集规模**：train 379 段 / val 147 段，约 131 分钟（train，@25fps），720p；
- **动作标注**：`multisports_GT.pkl`（已存 `data/raw/multisports/`）——篮球 18 类动作（pass/dribble/drive/2-point shot/3-point shot/free throw/block/rebound/steal/screen/pick-and-roll 等），共 **6247 个动作实例**；长尾明显（pass 1910 vs save 5）；tube = 逐帧 `[帧号,x1,y1,x2,y2]`；
- **视频无音轨**（仅 vide 轨）→ **解说词无法从视频 ASR 获得，文字直播是解说语料的唯一来源**；
- **意外收获**：画面自带比分栏（比分+节次+时间），后续可 OCR 作为解说的实时数据源；
- **下载注意**：HF 仓库是门控的（CC BY-NC 4.0，需登录勾选同意），hf-mirror 不转发认证，**必须直连 huggingface.co + Bearer token** 下载；样例文件在 `data/raw/multisports/`（GT pkl + sample_clip.mp4 + sample_frame.jpg）；
- **第一个模型定为球员检测（YOLO）**：动作识别的输入（tube）依赖检测器输出；检测数据已就绪（SportsMOT 5042 张），MultiSports 抽帧+tube 框可作第二训练源（同为转播视角）；动作识别放在检测之后（实验 5 视觉事件流的来源，先做 pass/dribble/shot 等高频类）。

课程三类来源的对应：**非结构化图像/视频** = 线①的视频与截帧；**非结构化文本** = 线②解说词；**结构化数据** = 线①动作标注转出的事件表。

## 3. 五实验链（v4）

```
线① → 实验2: YOLO 训练（截帧+球员框；动作标注另存）→ 实验3: 压缩（实时解说需要低延迟）
    → 实验4: Web 应用：上传视频 → 检测/轨迹/动作 → 事件时间轴页（原"数据页"取消）
    → 实验5: AI 解说员 Agent
        输入：视觉事件流（检测+动作，按时间轴）
        语言：RAG 检索解说语料 + LoRA 微调学风格
        输出：逐事件解说词 →（加分）TTS 语音
        旗舰演示：同一段视频 真人解说 vs AI 解说并排对比
```

变化点：实验 4 数据页（统计查询）取消，换"事件时间轴页"；胜负预测加分项（LightGBM）取消。
