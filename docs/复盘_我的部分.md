## 一、数据线（实验1，9/29–10/13）

**做了什么**：三条数据源采集→清洗→标准化→划分，并写数据卡留档。
- 视频：MultiSports（HF 门控仓库，15.55GB）→ 526 段 mp4；
- 图像：SportsMOT 篮球子集 2521 帧（×2 增强=5042）+ MultiSports tube 帧 7746 图/9094 框；
- 解说：逆向直播吧文字直播接口，**41 场 40,376 条**，33 字段清洗为 5 字段；
- 划分纪律：解说**按场次** 8:1:1（32,377/4,889/3,110）防同场泄漏。

**关键决策**：10-13 把数据布局切成 v2.0"视频/图像/解说"三条线，对齐最终产品"AI 解说员"——后面四个实验全部直接消费这套数据。
**证据**：`docs/DATA_CARD.md`、`DATA_DERIVATION.md`、`PROVENANCE.md`、`scripts/01~04`。

## 二、训练线（实验2 检测 + 实验3 压缩）

**做了什么**：先踩了全项目最大的坑，再重训翻盘。

1. **发现坏增强（_aug0 缺陷）**：torchvision v2 期望 tensor 输入，喂 numpy 后增强**静默失效**——增强副本全是原图 + 标签错位。脏口径复测只有 **0.419/0.420**（提交 1197ca8，对照证据在 `models/exp2_v2/` 与已归档的 415MB 坏增强数据）。
2. **v2 干净口径重训**（train 4316 / val 173 / test 190），四档对比（`models/exp2_v2/eval_test190.json`）：

| 档位 | mAP50 | mAP50-95 |
|---|---|---|
| A1 (yolov8n) | 0.990 | 0.749 |
| A2 (yolov8m) | 0.9932 | 0.7894 |
| **A2' (yolov8n) ← 选用** | **0.992** | 0.7585 |
| 蒸馏 dis3 | 0.9898 | 0.7569 |

3. **实验3 压缩**（`models/exp3_v2/eval_detail_v2.json`）：fp32 **0.9903** → INT8 **0.9902**，几乎无损；量化链 + 蒸馏消融 + 过拟合/协议检查全套证据（`quant_chain_v2/overfit_check/protocol_check`）。
4. 最终部署选 A2' INT8（val173 0.990，复测 clean190 0.988），CPU 推理约 56ms/帧。

**复盘点**：0.42→0.99 不是"模型变好了"，是**修对了数据**。这是"数据决定上限"最硬的一次实证，也是整个项目最值得讲的故事。

## 六、老师可能追问的 5 个问题（一句话答法）

1. **joblib 已 100% 为什么还微调？**——那 100% 是循环偏置（答案由规则生成，joblib 学的就是规则）；微调的真实价值是本地基座 79.1→94.2，且断网可用。
2. **mAP 0.42→0.99 靠什么？**——不是换模型，是修数据：坏增强静默失效导致标签错位，干净口径重训后模型结构没变、精度回来了。
3. **解说语料和视频对不上时间轴怎么办？**——承认对不上（不同比赛），改语义配对：事实来自视觉事件（t_ms/类型/人数），风格来自 3 万条真人解说 RAG。
4. **为什么 5 个工具而不是让大模型直接看视频？**——LLM 看不了视频；工具是把系统能力变成可调用接口，Agent 只负责编排与说话。
5. **INT8 损失多少？**——clean190 上 fp32 0.9903 → INT8 0.9902，无损级；CPU 56ms/帧，普通笔记本可演示。
