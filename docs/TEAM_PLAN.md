# 团队计划与下一步行动指南（实验 2–5）

> 给组员看的版本：先看"一、二"了解全局，再找到"四"里自己的角色，照着下一步清单做即可。
> 本版对应 **AI 篮球赛事解说员** 方案（v2.0，2026-10-13 起生效）；数据推导唯一事实来源见 `docs/DATA_DERIVATION.md`。

## 一、我们最终要做成什么

一个 **AI 篮球赛事解说员**（Web 应用）：上传一段比赛视频 →

1. **看得到人**：YOLO 检测每个球员（实验 2 训练、实验 3 压缩部署）；
2. **看得懂事**：识别场上发生了什么动作（传球/投篮/抢断…，MultiSports 动作标注）；
3. **说得出话**：大模型 Agent 结合解说语料风格，逐事件生成中文解说（实验 5）；
4. **旗舰演示**：同一段比赛视频，"真人解说 vs AI 解说"并排对比。

课程 5 个实验就是搭这个系统的 5 步，**每一步都用上一步的产出**：

| 实验 | 干什么（老师大纲） | 状态 | 产出 |
|---|---|---|---|
| 1 | 数据采集、清洗增强、标准化 | ✅ 已完成（新版三类数据已就位） | 视频 526 段 + 检测帧数据集 + 解论语料 4.0 万条 + 事件表 |
| 2 | 用实验 1 的数据训练模型 | ⬜ 就绪待训（脚本/数据包/冒烟全通过） | 球员检测模型 `best.pt` |
| 3 | 对实验 2 的模型做压缩优化 | ⬜ | 小而快的模型 + 优化前后对比报告 |
| 4 | 用实验 3 的模型做前后端开发 | ⬜ | Web 系统（上传视频 → 检测 + 事件时间线） |
| 5 | 在实验 4 上部署大模型 Agent（微调 + 工具调用） | ⬜ | **AI 解说员**（RAG + LoRA + 工具编排） |

老师只给了大纲，**具体技术方案小组自定**，下面三、四节就是我们定好的方案。

## 三、实验 2/3/4/5 具体做什么

### 实验 2：训练球员检测模型（YOLO）——**已可开工**

> 任务书全文见 `docs/实验2任务书.pdf`（4 阶段 + 报告 4 条硬性要求），对照结论：**YOLO 检测方案成立**。
> 任务书 2.2 的三个例子（分类/主题分类/图文匹配）均为"例如"性质示例，要求本质是"严格对应实验 1 的数据设计模型"——
> 我们实验 1 的图像标注是**逐球员框**（YOLO 格式），唯一合理匹配任务是检测，且检测是实验 3 压缩、实验 4 系统、实验 5 解说的事实基础。

- **一句话**：用 `data/splits/yolo/` 训练 YOLOv8，交出一个检测球员准的模型。
- **怎么做**（脚本现成 `scripts/03_train/train_yolo.py`，七组一键跑，设计详表见 `docs/EXP2_MODEL_SELECTION.md`）：
  - A1 yolov8n×原始 2158 / A2 yolov8n×原始+增强 4316 —— **消融必做**（A2-A1 即"数据增强→模型性能提升"因果验证，任务书报告要求第 3 条）；
  - B1/B2 同配置换 yolov8s 冲精度（n/s 对比即"模型规模选型依据"）；
  - C1/C2 = YOLO11n/s、D1 = YOLOv5n —— YOLO 系列代际对比（v5→v8→11 同档比精度与速度）；
  - 本机无 GPU：上传 `exp2_colab_pkg.tar`（818M）到 Colab T4 / AutoDL，`--run all --device 0`，单组约半小时；
  - **对比结论只在训练后出**：test 集 mAP + 统一条件测推理速度，填入 EXP2_MODEL_SELECTION.md 结果表。
- **任务书四阶段对应**（已写进 train_yolo.py 文档字符串）：
  - 2.1 环境：Colab 自带 CUDA/CuDNN/PyTorch；本地 CPU 冒烟即"基础环境与数据关联验证"（2.1.3）；分布式（2.1.2 选做）不做；
  - 2.2 选型：YOLOv8 n/s 两档，COCO 预训练迁移学习；
  - 2.3 训练优化（必做项已全部启用）：AMP 混合精度（amp=True 自动）、早停（patience=30）、余弦学习率调度（cos_lr=True）、梯度累积（ultralytics nbs=64 机制，batch16 隐式累积 4 步）；
  - 2.4 适配（选做）：LoRA 留实验 5 用解说语料完成，报告注明。
- **交付物**：`best.pt` + 每组 `results.csv`；报告含超参表（args.yaml 照抄）、损失/mAP 曲线、PR 曲线、混淆矩阵、好坏案例截图。
- **报告"数据-模型关联表"（任务书硬性要求第 2 条）骨架**——写报告直接抄：

| 实验 1 数据特点 | 实验 2 模型选型/优化策略 |
|---|---|
| 图像 5042 张（含 2158 增强副本，640×640） | YOLOv8n（轻量）为主，YOLOv8s 对比规模收益 |
| 标注为逐球员框（YOLO 格式，单类） | 检测任务而非分类；COCO 预训练迁移弥补从零训练数据量不足 |
| 近重复帧已剔除（2460 张） | 避免训练/验证泄漏导致虚高 mAP（问题分析关联实验 1 预处理的素材） |
| 增强 = 水平翻转+仿射+色彩抖动（框同步） | A1/A2 消融直接验证增强因果收益 |
| 按序列划分（防同比赛泄漏） | 与检测泛化目标一致：验证集考"没见过的比赛" |
| 类别单一（player），长尾在动作层不在检测层 | 检测层无需 class_weight；不平衡问题留给实验 5 动作识别 |

### 实验 3：模型压缩优化

- **一句话**：把 `best.pt` 压得更小、跑得更快，精度尽量不掉。
- **怎么做**：`yolo export` 导出 ONNX + INT8 量化；有 NVIDIA 卡可加 TensorRT。
- **交付物**：优化模型 + 压缩前后对比表（体积/参数量/FLOPs/CPU-GPU 推理耗时/mAP）。
- 剪枝/蒸馏工作量大，时间不够写进报告"展望"。

### 实验 4：前后端开发（系统成形）

- **一句话**：把检测模型和事件数据包成网页应用（AI 解说员的"身体"）。
- **后端（FastAPI）**：
  - 检测 API：图片/视频 → 实验 3 的优化模型 → 球员框坐标；
  - 事件 API：events.csv 导入 SQLite，按视频/时间段查 18 类动作（解说的事实来源）。
- **前端**：检测页（上传画框）+ 事件时间线页（ECharts 展示动作分布）；技术栈 Vue3 或纯 HTML+ECharts 均可。
- **交付物**：能跑通的系统 + 架构图 + 页面截图。

### 实验 5：大模型 Agent —— **AI 解说员（产品核心）**

- **一句话**：让 LLM"看着"检测与事件流，用解说员的口吻说比赛。
- **四块拼图**（按优先级）：
  1. **RAG**（零依赖，立刻可开工）：解说语料 40,376 条入向量库，检索"类似局面下真人怎么说"；
  2. **LoRA 微调**（Qwen 小模型）：用 (画面事件特征, 解说词) 指令对学风格——指令对构造是实验 1 遗留增强任务（把 events.csv 的动作/时间/位置特征与解说词按时间对齐）；
  3. **工具调用**：把实验 4 的检测 API、事件 API 注册为 Agent 工具；
  4. **动作识别**（可降级）：理想路线用 MultiSports tubes 训动作模型；时间紧直接查 events.csv（GT 代打），演示效果相同。
- **旗舰演示**：同一段 MultiSports 视频，左真人解说字幕、右 AI 实时解说，逐事件滚动对比。

## 五、项目的现实意义 + 加分项

### 现实意义怎么说（AI 解说是真实产业）

- **AI 解说已商用**：百度、网易、腾讯等在体育转播中落地 AI 解说/智能字幕；SRT/统计驱动的自动赛事播报是体育媒体标准能力——我们的项目就是这条业务线的微缩闭环；
- **检测是第一步**：NBA 官方球员追踪系统（Sony Hawk-Eye / Second Spectrum）从检测/跟踪起家，自动集锦、战术复盘都建立在"看得见人"上；
- 换个领域（电竞、安防、工业巡检），"视频理解 + 领域语料 + LLM 生成"的架构不变——答辩强调**闭环完整**。

### 加分项（砍掉不影响主线）

| # | 加分项 | 一句话 | 在哪做 | 负责 | 依赖 |
|---|---|---|---|---|---|
| 1 | **跑位热力图**（优先） | 检测框接 ByteTrack 串轨迹生成热力图，"教练视角战术分析" | 实验 3 备算法 / 实验 4 出功能 | B（算法）+C（API）+D（前端） | 实验 2 `best.pt` |
| 2 | **比分栏 OCR** | MultiSports 画面自带比分栏，OCR 出实时比分喂给解说 Agent，解说信息更丰富 | 实验 5 | E | 无 |
| 3 | **双模型动作识别** | 不查 GT、真训一个动作识别模型（MultiSports tubes，SlowFast/TimeSformer） | 实验 5 | E | GPU |

优先级：**1 > 2 > 3**。时间紧只做第 1 条——成本最低（ByteTrack 现成库），视觉冲击最强。

### 答辩一句话

> "我们做的是 AI 赛事解说员：检测模型看人、动作识别看事、大模型用真人解说的语言学风格说话——对应体育转播里 AI 解说与球员追踪两条真实业务线；把篮球换成任何领域视频，'视频理解 + 领域语料 + LLM 生成'架构不变。"
