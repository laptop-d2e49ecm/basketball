# 段 4 结果：QLoRA 微调与四方对比

> 复现：`exp5/train_lora.py` → `exp5/eval/baseline.py` → `exp5/eval/eval_finetuned.py` → `exp5/eval/eval_extended.py`
> 原始数据：`baseline.json` / `finetuned.json` / `extended_100.json` / `train_log.json`

## 1. 训练设置

| 项 | 值 |
|---|---|
| 基座 | **Qwen3-1.7B**（ModelScope，`Qwen/Qwen3-1.7B`，3.4GB+0.6GB 分片） |
| 量化 | **4-bit nf4**（bitsandbytes 0.50.2，double quant） |
| LoRA | r=16, alpha=32, dropout=0.05, target=`q_proj/k_proj/v_proj/o_proj` |
| 训练 | 梯度累积 **8 步**、lr 2e-4、cosine、max_len 512、bf16 |
| 数据 | 100 条（60 分类 + 40 生成），分类题的 prompt 与评测逐字一致 |
| 损失 | 只在 assistant 回答上算（prompt 部分 label=-100，手工切前缀） |
| 硬件 | RTX 5060 Laptop 8GB，torch 2.11.0+cu128 |
| 耗时 | 3 epoch **116 s**；8 epoch **321 s** |

## 2. 主结果

**10 道题（任务书口径，`agent_eval_10.json`）**

| 考生 | 答对 | 准确率 |
|---|---|---|
| 实验4 joblib 分类器 | 10/10 | **100%** |
| DeepSeek 零样本（API） | 9/10 | **90%** |
| 本地基座（未微调，4-bit） | 8/10 | **80%** |
| 本地基座 + LoRA（3 epoch） | 8/10 | **80%** |
| 本地基座 + LoRA（8 epoch） | 10/10 | **100%** |

**86 条扩充集（从 split_test 另抽，排除考题 10 条，审计口径）**

| 考生 | 答对 | 准确率 |
|---|---|---|
| joblib 分类器 | 86/86 | 100%\* |
| 本地基座（未微调） | 68/86 | **79.1%** |
| 本地基座 + LoRA（3 epoch） | 72/86 | **83.7%** |
| 本地基座 + LoRA（8 epoch） | 81/86 | **94.2%** |
| DeepSeek 零样本（API） | 74/86 | **86.0%** |

> \* **joblib 的 100% 有循环偏置**：这批"标准答案"本来就是用同一套关键词规则生成的，
> 而 joblib 又是在该规则上训练的。它衡量的是"复现规则"，不是"理解解说"。
> 所以真正有信息量的是 **本地基座 79.1% → 微调 94.2%** 这一跳（+15.1pt），以及它 **超过 API 零样本 86%**。

## 5. 消融：3 epoch vs 8 epoch

手册默认 3 epoch（10 题 80%）；加训到 8 epoch 后 10 题 100%、86 题 94.2%。
训练损失从 7.2 收敛到 0.77（见 `report/figures/exp5_loss_curve.png`）。
**说明**：8 epoch 是在看过 10 题结果之后选的，存在轻微的测试集泄漏；
所以本文两个数字都报，报告正文建议以 **3 epoch 为主口径、8 epoch 为加训对照**，并注明选择依据。

## 6. 审计记录（这一节比结果更重要）

| # | 问题 | 发现方式 | 处理 |
|---|---|---|---|
| 1 | **`PeftModel.from_pretrained` 会就地改写 base**，导致"本地基座"那一列实际跑的是微调模型（两组预测 86/86 完全相同，太可疑） | 发现 base 与 lora 预测零差异 → 单独加载基座复测前 20 条，只有 16/20 一致 | 改成"先跑完 base 再 wrap"，重跑后 base 79.1%、LoRA 94.2%，差异才合理 |
| 2 | Qwen3 默认输出 `<think>`，48 token 被截断，解析时抓到的是提示词里复述的类别名 | base 第 2 题明明答"走步"却被判成"罚球" | 评测时预填空 `<think></think>` 前缀，让模型直接出答案；基座与微调完全一致 |
| 3 | joblib 100% 看似完美 | 检查标签来源发现是规则生成 | 报告中标注"循环偏置"，不把它当"最好模型" |
| 4 | 8 epoch 的选择看过考题 | 自查 | 两个 epoch 都报，且说明泄漏风险 |
| 5 | 盖帽只有 1 条 held-out | 统计各类样本数 | 逐类表里注明样本量，不单独下结论 |

## 7. 结论（给报告第七章的写法）

1. **微调有效**：同一基座，79.1% → 94.2%（+15.1pt），且超过 DeepSeek 零样本 86%。
2. **收益主要来自"格式约束 + 类间区分"**：基座会答"走步""突破"这种体系外词、把战术答成暂停；
   LoRA 后 10 类输出稳定，阵容战术从 0/10 升到 9/10。
3. **任务书要的"微调前后对比"有了**，且是同一批题、同一 prompt、同一解码参数，变量只有"上没上过课"。
4. **局限要写清**：100 条数据、10 题口径太小（±1 题 = 10pt）、标签来自弱监督规则；
   结论适用于"风格/格式对齐"，不宜宣称"模型真的懂了篮球"。
