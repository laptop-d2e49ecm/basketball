## 5.2 量化前后对比：模型单条推理（10 句 × 3 轮）

| 指标 | 4-bit (nf4) | fp16 | 差异 |
|---|---|---|---|
| 单条延迟（3 轮均值 ± 标准差） | **293.8 ± 38.5 ms** | **241.8 ± 30.6 ms** | fp16 快约 **18%** |
| 各轮均值 | 338.1 / 274.5 / 268.8 | 277.0 / 226.7 / 221.6 | 同向 |
| P95（30 次合并） | 418.8 ms | 294.6 ms | fp16 更快 |
| 显存峰值 | **1.30 GB** | 3.25 GB | **省 60%** |
| 冷启动加载 | 8.3 s | 8.5 s | 基本持平 |

**结论**：1.7B + 短输出场景下，**4-bit 不降延迟**（反量化开销抵消带宽收益），
**真正的收益是显存**（1.3 vs 3.25 GB）。

## 5.2b Agent 链路对比（真实 /agent/chat，10 次/模式）

| 指标 | 4-bit | fp16 | 差异 |
|---|---|---|---|
| 工具耗时（均值 ± 标准差） | 240.1 ± 52.0 ms | 224.9 ± 38.1 ms | fp16 快 6% |
| 工具 P95 | 318 ms | 271 ms | — |
| **端到端均值** | **2198.9 ms** | **2179.2 ms** | **0.9%，噪声级** |
| 端到端 P95 | 2699 ms | 2558 ms | — |

**结论**：端到端 2.2 秒里 DeepSeek API 占约 2.0 秒，本地模型只占 0.22–0.24 秒。
**换量化方式对"Agent 响应时间"几乎没有影响**；报告的层次要写清：模型耗时 ≠ Agent 响应时间。

## 5.4 异常注入（契约 §4 的错误码表）

**A. 错误码映射（TestClient + 伪造 agent，6/6 通过）**

| 场景 | 期望 | 实际 | 返回 msg |
|---|---|---|---|
